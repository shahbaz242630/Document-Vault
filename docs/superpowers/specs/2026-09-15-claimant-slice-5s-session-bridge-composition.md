# Slice 5S — synthetic claimant session-to-bridge composition

Selected on 2026-09-15 after Slices 5Q and 5R merged in PRs #79 and #80. Add one isolated, literal-false mobile harness that composes an injected synthetic claimant-portal session source with the existing possession-to-handoff bridge. This slice must not create an authentication client, read ambient auth state, or connect the bridge to a normal app route.

The session source must synchronously establish one fresh, non-recovery AAL2 `claimant_portal` session before the bridge can be created. The harness freezes the exact user ID, portal-session ID and session version for its lifetime. Missing, malformed, stale, expired or later changed session state closes the harness permanently, disposes the bridge and clears any pending draft or retry authority. A session that changes and later reverts remains invalid.

One strictly ordered injected lifecycle source controls the harness and the child bridge. Only foreground permits an explicitly requested attempt or retry. Inactive/background cancels the child operation, clears any accepted draft and requires a new foreground event before a fresh attempt. Lock, session end, disable, malformed or regressing lifecycle events close permanently. Late results after cancellation, session invalidation or disposal are suppressed.

A successful bridge completion is reduced to a frozen, value-free draft summary. The summary may state only `state: draft`, `route_profile: offline_code_v2`, `claimant_session_bound: true`, `case_created: true`, the case version and false identity/relationship/intake/review/release authority fields. It must not expose the case ID, user ID, session ID, bearer token, source challenge, binding digest, signature or replay detail. The underlying API and bridge remain authoritative; the harness grants no claimant role, review authority or release authority.

Acceptance: dormant-by-default dependency non-access; invalid composition fail-closed; synchronous session establishment; exact injected synthetic success; safe draft-result reduction; session change/revert denial; stale/expired session denial; foreground gating; background cancellation and late-result suppression; terminal and hostile lifecycle ordering; explicit cancellation; retry delegation only within the unchanged foreground/session scope; awaitable disposal; static rejection of activation, ambient authentication/network/native/storage adapters and normal runtime importers; focused tests, mobile typecheck, lint and existing claimant isolation/security regressions.

No hosted MFA/Auth integration, UI/navigation, normal runtime importer, production native custody or signer, persistent session or draft storage, server/database change, hosted mutation, deployment, native/EAS build, real claimant data, downstream intake/review/release behavior or capability activation is included.
