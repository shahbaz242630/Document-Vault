# Slice 5T — synthetic claimant-portal session client

Selected on 2026-09-15 after Slice 5S was published in PR #84 and retargeted to `main`. Add one independently literal-false, runtime-disconnected mobile client for the existing claimant-portal session activate, assert and revoke HTTP boundary. The client uses only injected transport and synthetic authenticated-session material. It must not import Supabase, the normal authentication stack, application routes, storage, native adapters or ambient network access.

Activation accepts one exact synthetic fresh-AAL2, non-recovery authenticated session plus a UUIDv4 idempotency key. The request path, HTTPS API and claimant origins, bearer header, origin, JSON content type, empty object body and idempotency header are fixed by the client. Strict responses require the claimant origin, `no-store`, `nosniff`, a safe result envelope, `claimant_portal` context and a positive server-issued session version. Client-supplied user/session identifiers are never sent in the body; the API derives them from the bearer token.

The client retains at most one validated session in memory and exposes it through a synthetic-only subscription source. A subscriber receives the current session synchronously when one exists. Assert must preserve the exact user ID, session ID and server session version. Revoke must return explicit revoked truth, clear the in-memory session and emit only a generic unavailable event. Changed/malformed responses, authentication drift, expiry, stale assurance, overlapping operations and use after disposal fail closed. Cancellation suppresses late results and clears pending retry authority without revoking server state.

Only an ambiguous activation or revoke dispatch may be retried, using the exact original URL, headers and body within the unchanged authenticated-session binding. No automatic retry, token refresh or operation is allowed. An ambiguous assert result has no mutation retry authority and requires an explicit fresh assert. Snapshots are value-free and expose no bearer, identity, session ID, session version or idempotency key.

Acceptance: dormant-by-default dependency non-access; invalid composition fail-closed; exact activate/assert/revoke requests and strict responses; server-derived session version; synchronous memory-only session source; no user/session IDs in bodies; response/header/status rejection; session binding drift; stale/expired/recovery/AAL1 denial; overlap; cancellation and late-result suppression; exact activation/revoke retry; no assert retry; awaitable disposal; static rejection of activation, ambient auth/network/native/storage adapters and normal runtime importers; focused tests, mobile typecheck, lint and existing security/isolation regressions.

No hosted MFA/Auth integration, Supabase SDK, UI/navigation, lifecycle or 5S wiring, persistent session storage, native custody/signing, server/database change, hosted mutation, deployment, native/EAS build, real claimant data, downstream intake/review/release behavior or capability activation is included.
