# Slice 5T — synthetic claimant-portal session client verification

Date: 2026-09-15 (Asia/Dubai). Branch: `codex/claimant-portal-session-client`, based on Slice 5S PR #84 head `c58d4b4` while its exact-head merge watcher remains active.

The new mobile client is independently literal-false and disconnected from normal runtime. It uses only an injected request transport and synthetic authenticated-session material to call the existing claimant-portal session activate, assert and revoke HTTP paths. Requests fix the HTTPS API/claimant origins, bearer/origin/content-type/idempotency headers and empty object body. User and session identifiers never appear in request bodies; the existing API remains responsible for deriving them from the bearer token.

Strict response handling requires status 200, bounded JSON, exact claimant origin, `no-store`, `nosniff`, `Vary: Origin`, an exact result envelope, claimant-portal context and a positive server session version. Activation retains one fresh non-recovery AAL2 session in memory and exposes it synchronously through a synthetic-only subscription source. Assert preserves the exact server version. Revoke requires explicit revoked truth, clears local session state and emits only generic unavailability.

Only ambiguous activation and revoke dispatches retain bounded exact-request retry authority. Assert never stores retry authority. Overlap is rejected; cancellation and disposal suppress late results before local state commit. Snapshots contain only generic status/session/retry booleans and expose no bearer, user ID, session ID, version or idempotency key. Static isolation rejects activation, ambient network/auth/Supabase/native/storage access and normal application importers.
